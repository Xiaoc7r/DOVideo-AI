| P1 | 新修订已排队，但旧结果尚未被消费者清理。状态查询优先返回旧结果，SSE 因此过早结束，页面把旧结果当成本次修订结果。 | 读取未应用的修订标记和 active 状态，有正在排队的修订时优先返回 QUEUED；没有活跃修订时仍能读取已有结果。测试覆盖这两个分支。 |
| P1 | 控制器先查询初始状态、再注册 SSE；两步之间完成的任务可能只留下过期的 PROCESSING 快照，连接一直等不到完成。 | 先原子注册订阅，再通过 supplier 查询初始状态。每个订阅串行发送，已收到实时事件时丢弃迟到初始快照，终态关闭后不再发送。转写快照在订阅后重新读取媒体。MockMvc 用例在快照读取过程中发布完成事件，验证只收到完成状态。 |

| P2 | 同一媒体的结果复用也执行跨媒体的上下文转换，将原始证据帧引用替换为时间戳占位，影响后续追问与证据使用。 | 同媒体复用保留原始上下文；跨媒体复用继续本地化引用，并在源上下文缺失时拒绝复用。测试检查三种情况。 |

## 升级和验证边界

本轮修改了分析任务 active、attempts 和任务锁的归属范围。部署时应协调更新 API 与消费者，先暂停接收新任务并排空旧消费者的在途任务，再切换版本；不要让仍使用内容级 active 键的旧实例与新实例混合处理任务。已有完成结果的内容缓存键及业务数据库结构保持兼容；列表缓存升级为 v3，旧数据按原 TTL 自行过期。本轮仅提交代码，没有操作线上部署。

同内容任务通过可中断的 Redisson 内容锁等待前一份结果，保留已有的结果复用及算力节省行为。等待会占用消费者线程，锁持有依靠 watchdog；本轮用模拟对象验证等待后的业务行为、重试和释放路径，没有完成真实 Redis 锁、消费者饱和或跨进程故障压力测试。

本地未配置真实运行用 `.env` 和模型服务凭据，没有使用真实 ASR/LLM、MySQL、Redis、RocketMQ、MinIO 或 Qdrant 完成视频全链路联调。浏览器使用 demo 数据；后端和扩展测试使用模拟依赖。因此本报告不声明生产全链路已经验证或不存在其他缺陷。

仍沿用上一轮记录的跨存储边界：MySQL、Redis、对象存储和消息队列没有统一事务或 outbox。本轮未新增持久事件日志、跨重连事件重放或全局恰好一次保证。SSE 用例覆盖已确认的注册与快照竞态，不穷举所有线程调度。
